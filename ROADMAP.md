# Roadmap

Ayni Orchestrator requirements, priorities, and delivery status are maintained in
the private [organization Project](https://github.com/orgs/ayni-oss/projects/2)
and its linked [issues](https://github.com/ayni-oss/orchestrator/issues).

An issue is the source of truth for its outcome and acceptance criteria.
Priority labels plus Project status and iteration fields provide backlog and
roadmap views. Pull requests link the issue with a closing keyword so delivery
remains traceable without duplicating plans or completed-work records in
repository documentation. Completed delivery phases are recorded in the
repository's [closed GitHub milestones](https://github.com/ayni-oss/orchestrator/milestones?state=closed)
and their assigned pull requests.

Ayni CLI work is planned independently in the
[Ayni CLI Project](https://github.com/orgs/ayni-oss/projects/1). When work spans
both products, the private Orchestrator issue may link the public Ayni issue; the
public issue must not expose private Orchestrator material.
