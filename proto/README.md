# Private orchestrator API

The canonical package is `ayni.orchestrator.v1`. M1 records the intentional breaking baseline `workflow-m1-private-v1` in `BASELINE`.

## Slice 1 production surface

The trusted-loopback control-plane listener registers only:

- `ProjectService.CreateWorkspace`;
- `ProjectService.CreateProject`;
- `ProjectConversationService.CreateConversation`;
- `ProjectConversationService.SendMessage`;
- `ProjectConversationService.GetConversationSnapshot`;
- `ProjectConversationService.ListConversationHistory`;
- `ProjectConversationService.WatchConversation`, which returns `UNIMPLEMENTED` until M1 Slice 3.

`workflow.proto` defines server-issued command receipts, scheduling/dispatch/execution/presentation states, messages, turns, activities, bounded terminal summaries, snapshots, history records, updates, and watch frames. Removed workflow RPCs have no compatibility adapter.

The listener binds to pod loopback. Canonical sources and generated bindings do not imply a public endpoint, custom-client contract, browser API, or published SDK.

## Generation and compatibility

Do not edit generated files. From the repository root:

```sh
buf format -w proto
buf generate
scripts/ci/check-proto.sh
scripts/ci/check-workflow-private-v1-feasibility.sh
```

Rust descriptors are generated by `ayni-orchestrator-api`; TypeScript output lives in `clients/typescript/src/generated`. JavaScript 64-bit integers are decimal strings.

The PR workflow allows the one-time reset only when the base marker is the former baseline and the candidate marker is exactly `workflow-m1-private-v1`. Once established, routine changes run Buf FILE compatibility against the base contract. Changing the marker again requires a separately approved coordinated reset.

The `ayni.orchestrator.events.v1` workflow payloads define exact application-to-executor command bytes and later-slice report/decision envelopes. In Slice 1, PostgreSQL persists exact command-event outbox bytes, but no production broker or executor is deployed.
